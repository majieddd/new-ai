# Contributing and reproducing

Work on a feature branch and submit a reviewed pull request. Cloud AI Generalist owns model execution/integration and final publication; Builder owns packaging/site implementation; Researcher owns living-paper content; Energy Model Engineer and Evaluation Scientist retain their existing implementation/independent-evaluation scopes.

## Evidence before claims

Record producing commit, command, environment, safe raw developmental receipt, hashes, measured units, sample count, failures and limitations. Distinguish implemented, exercised, proposed, not run and blocked. Energy decrease is a diagnostic, not proof of improved answers. Unchanged backbone weights do not guarantee unchanged routed capabilities.

Do not mutate historical results, preregistered gates, evaluators or final material. GPU training is not part of CI. Update accepted milestones through status/receipt validation, local build, tests, source/links and diagram consistency checks, then reviewed PR and Pages. Retain earlier paper versions and negative results. No automatic training or automatic scientific conclusions.

## Public source boundary

Stage only an explicit source whitelist. Exclude credentials, `.env`, private relay logs, final questions/answer keys, uncleared datasets/models/weights, PDFs and private working history. Third-party code, model, data and document rights require separate provenance; Apache-2.0 covers original code, not everything cited. Run the publication safety check before pushing.

## Attribution

Use repository-local git identity for the actual author. Do not assign human co-authorship or DCO sign-off merely for requesting/reviewing work. Include other material authors only when supported. Never force-push or directly modify historical live artifacts.
